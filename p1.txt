## Capability Dependency Planning

When creating a Skill, identify all capabilities required to make it operational.

1. Define the Skill's intended workflow and reusable purpose.
2. Identify the Tools and other Skills required by that workflow.
3. Search the existing Capability Registry for suitable dependencies.
4. Prefer composing existing capabilities.
5. If necessary, propose upgrading existing capabilities before creating new ones.
6. For genuinely missing capabilities, use the `create_tool` or `create_skill` workflow to prepare reusable implementations.
7. Produce one coordinated development proposal containing the Skill, required capability changes, dependency relationships, source code, tests, and security assessments.
8. Allow the user to review the proposal as a whole while approving and classifying each new or upgraded capability individually.
9. Do not activate the Skill until all mandatory dependencies are available and authorized.

Avoid creating duplicate capabilities or unnecessary dependency chains.

Dependency planning is part of Skill creation. It does not require a separate Skill or special-purpose Agent Controller logic.
